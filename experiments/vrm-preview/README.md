# 独立 3D 预览试验台

本地 VRM 验证项目，和 Live2D 扩展分开运行，不调用 AI、不安装形象、不改 Coo 配置。

## 启动

双击 `start.cmd` 会启动本地服务并自动打开浏览器；服务已经运行时直接复用，不再启动第二份。
也可在此目录运行 `npm start`，手动打开终端输出的地址。默认端口是 `4783`，仅监听 `127.0.0.1`。
页面地址应为 `http://127.0.0.1:4783/`。直接从资源管理器打开 `index.html` 时会自动转到这个地址；
这仍要求服务先启动。自定义端口时通过 `start.cmd` 或终端输出的地址进入。
依赖固定为 Three.js 0.180.0、three-vrm / three-vrm-animation 3.4.2 和 esbuild 0.25.10。
本机已在本目录安装；新副本先执行 `npm ci`。也可用 `VRM_ENGINE_ROOT` 指向已安装全部同版本依赖的项目。
构建产物和进程记录位于忽略的 `.local/`，源码独立位于本目录。

可以点击「打开 VRM」或拖入单个 `.vrm`，文件直接在浏览器内读取，不上传、不复制素材。
默认只读引用旧工作台的原始 `aldina.vrm`。可用环境变量 `VRM_SAMPLE` 换成本机另一个样本；
不存在样本时仍可自行打开 VRM。样本是用户已有的本地练习素材，不包含在项目或构建产物中。

## 可以查看什么

- VRM 0.x / 1.0 的人形骨骼加载、MToon 贴图和模型自带的弹簧物理；当前实测样本是 VRM 0.x。
- 旋转、缩放、平移、全身和面部取景，浅色／深色／网格背景，截图。
- 默认开启自主互动：三段 Overte / Hanami VRMA 待机，配合视线停留、移开和重新关注；轻点模型触发回应。
- 眼睛、头部、上身依次跟随，眨眼采用不等间隔。点击回应带冷却，拖动旋转、点空白和手动动作期间不抢播。
- 待机、招手、点头、摇头、鞠躬、原地走路六种手动试动作，使用关键帧混合和姿态衔接；停止后平稳回到待机。
- 手势幅度为 30%–100%，保留成品待机姿态，避免把整个骨架放大变形。
- 站立时双腿使用两节骨骼 IK 保持足部位置和方向。原地走路试播会释放接地约束，结束后逐步恢复。
- 模型实际声明的全部表情，保留原名称，单选试用、强度调整，以及眨眼、视线和说话口型试播。
- 姿态动作和面部表情可叠加；表情平滑进入和退出，手动选择优先于自动微笑；眨眼和口型遵守模型覆盖规则。
- 暂停会冻结身体、注意力与计时，仍可旋转观察及手动调整表情。系统要求减少动态效果时默认暂停并关闭自主互动。
- 实际几何、骨骼、贴图尺寸、渲染读数，以及暂停、恢复、复位与重复换模型。

基础待机使用许可与来源已保留的 Overte / Hanami 动画，手动手势及备用待机使用本项目原创关键帧。
统一通过官方 three-vrm-animation 做 VRM 0.x / 1.0 坐标映射与髋部尺度适配；不识别模型自带动画。
当前 VRMA 只加载随项目的三个固定文件，尚未开放用户动作导入；没有接入 VMD、PMX、音频舞蹈、桌面运动或 Coo Body/kit。
口型开关仍是试播，没有接入真实音频。原地走路仅用于观察骨骼驱动，不保证足底锁定。
模型原始骨骼比例、贴图、表情和物理参数不被写回、裁剪或重编码。控制台可能显示源 VRM 的旧版规范兼容提示。

导入只接受自包含的 VRM / GLB 容器；拒绝外部贴图或缓冲链接，避免意外联网。单文件上限为 128 MiB。
文件损坏或不支持时保留已经载入的模型；新模型解析成功后才释放旧模型。WebGL 上下文丢失时提示刷新。

## 验证

`npm test` 核对 GLB 格式、外部资源限制、关键帧连续性，以及注意力、冷却、暂停和一分钟行为调度。
浏览器实测记录保存在忽略的 `artifacts/`，架构与检查记录见 [DEVELOPMENT.md](./DEVELOPMENT.md)。
独立预览通过不等于通过 Coo 形象沙箱或扩展契约；此项目不是 World 扩展，不执行扩展安装检查。

## 许可

自有代码沿用主项目许可。Three.js、three-vrm 和 three-vrm-animation 采用 MIT，构建时把对应许可保存到
`.local/THIRD_PARTY_LICENSES.txt` 并在页面提供入口。模型素材受各自许可约束，不随本项目分发。
三段待机动画的 Apache-2.0、完整上游声明和来源摘要随素材保留，详见 [THIRD-PARTY.md](./THIRD-PARTY.md)。
本轮多个参考项目的选择依据见 [DRIVER-SELECTION.md](./DRIVER-SELECTION.md)。

官方加载流程依据：[three-vrm 3.4.2](https://github.com/pixiv/three-vrm/tree/v3.4.2/packages/three-vrm)。

## 本机验证记录（2026-11-02）

用未压缩的 aldina.vrm 在本机 Chrome 的真实 WebGL 环境验证：28,492 个源三角面、53 个人形骨骼、
17 个表情、最大贴图边 2048。招手叠加开心、六种试动作、循环与结束归位、暂停后调整表情、
口型、全身／面部取景、透明截图、损坏文件回退与说明弹窗通过。三个连续重新加载后的 GPU
纹理和几何数量保持一致；源模型 SHA-256 未变化。1440／900／720／540／390 宽度无横向溢出。
测试过程没有页面错误或对外请求。记录及截图位于忽略的 `artifacts/`。

这只证明上述样本和独立浏览器路径；VRM 1.0、其他体型、长时间资源稳定性及 Coo 沙箱尚未实测。

自主互动验证：真实浏览器连续采集 376 个状态样本，含 40 秒无操作待机、分层注视、点击回应、
冷却、动作过渡、暂停后旋转与改表情、关闭自主互动、三次重载和五种宽度检查。
双脚在标准骨架和实际渲染骨架中保持站立目标位置；未出现姿态累积，GPU 纹理和几何数量稳定。
系统减少动态效果的初始状态通过。模型摘要未变化，无页面错误或对外请求。
视频 `artifacts/life-demo.webm` 为真实预览画布录制；此结果不能推断任意模型均达到同样表现。

切换到官方动画适配和 Overte 待机后重新完成连续运行检查（超过 360 次状态采样），两个 VRM 坐标约定的合成骨架
鞠躬前倾测试均通过。真实完整模型仍只实测 VRM 0.x，不能把合成骨架测试当作 VRM 1.0 整模验收。

入口排障：用户截图中的纯文字页面来自 `file:///…/index.html`。旧入口使用站点根路径，
本地文件直开时样式和脚本缺失。现以相对经典脚本处理文件入口跳转，HTTP 入口保持同源 CSP；
启动器等待服务就绪后再打开，端口被其他程序占用时拒绝误用。该修复不修改 Coo 或模型素材。
