# 本机成品行走参考

这是 VRM Game Starter 的独立本机副本，固定来源为
`norio/vrm-game-starter@b14c236fd8150855348ad085b7820c298eac4b30`。
原始 README 与 MIT 许可证保留在同目录，原始逐文件 Git 摘要和省略列表见 `UPSTREAM.json`。

本轮直接复用它的 BVHEcctrl 胶囊角色控制、碰撞、动画状态切换、转向、相机与 Foot IK。
本地按钮只向原控制器提供方向和走跑输入，不另写一套位移或腿部步态。
走跑使用上游 Quaternius 动画库。停步使用上游动作交叉淡化，不声称有独立的起停脚步匹配或运动匹配系统。

## 打开

本机地址：`http://127.0.0.1:4785/`。
已经安装依赖的副本双击 `start.cmd`；启动器先构建，再启动仅监听回环地址的服务，端口已有本服务时直接复用。
新副本先执行 `npm ci --ignore-scripts`。手动运行可以执行 `npm run build` 后 `node server.mjs`。
`node launch.mjs --no-open` 只启动服务，不打开用户浏览器。

- 「走几步」「跑一段」「停下」「复位」用于直接比较效果。
- WASD／方向键移动，Shift 跑步，空格跳跃，拖动视角；上游仍包含游戏手柄和触屏输入，本轮未实测。
- 「打开 VRM」或拖入 `.vrm` 可更换模型；「调参」展开上游控制器、脚部 IK、镜头和场景检查器。
- 顶部版本沿用 0.1.0。底部入口可返回原来的动作／交谈试验台。

默认模型只读引用用户已有的 `aldina.vrm`，也可用 `VRM_SAMPLE` 指定另一个绝对路径。
不随源代码或构建产物分发任何模型。未下载上游的两个 VRoid 模型。
模型在本机浏览器读取，不上传；本地服务器只提供读取接口。

## 对上游的修改

1. 替换样本地址，增加本地静态服务、启动器、直接试走按钮与只读诊断。
2. 导入前检查自包含 VRM 容器，拒绝外部图片／缓冲引用，保留旧模型直到新模型加载成功。
3. 修正可选骨骼处理：原工程要求全部映射骨骼存在，导致没有 `upperChest` 的合法模型加载失败。
   现在仅检查官方必需骨骼，保留完整源动画骨骼链，向目标实际存在的最近祖先计算局部旋转。
   被省略上胸骨的运动会传递至颈部和肩部；缺失必需腿骨仍报错。
4. 为检查走动流畅度，默认关闭 AO、TRAA，阴影改为 2048，像素比上限 1；检查器仍可调整。
5. 模型更换诊断增加加载序号，避免将尚未开始的第二次同名加载误认为已经完成。

重复加载四次时，GPU 几何保持 57；纹理从冷启动的 26 升至 38 后，在后三次采样保持 38。
这是本次短时观察到的稳定上限，不把冷启动读数当作重载后的固定数量，也不代替长期显存检查。

## 检查

`npm run typecheck`、`npm test`、`npm run build`。
49 项测试通过，省略的上游两个模型夹具对应 1 项测试明确跳过；可选上胸骨传播和必需腿骨错误另有回归测试。
浏览器实机范围、视频和采样结果见上级 `DEVELOPMENT.md` 与忽略的 `artifacts/`。

构建仍有上游 three-vrm 的旧 `tslFn` 后备导出警告和包体大小提醒；实测的当前路径没有运行错误。
此副本是完整角色控制的效果参考，不是已经完成的桌面宠物或 Coo 接入。
VRM 1.0 整模、复杂服装、多模型比例、长时运行和任意地形均需另外验收。
