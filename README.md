# Live2D 模型一键安装

把本地 Live2D 和 BongoCat 模型转换成 Coo / Coopanion 可用的形象包，生成封面并安装。每份产物保留为卡片，右上角显示模型类型。Live2D 支持适配通用动作与表情。

这是运行在 Coo 内的 World 扩展。导入、转换和安装在本机完成，使用扩展无需另装 Node.js，也无需手动启动浏览器。默认使用面板；开启 AI 自动适配后，Coo 可以识别模型、分析原生动作并提出安装方案。模型元数据与所选关键帧通过 Coo 当前模型分析，本项目不附带模型素材。

## 兼容范围

当前版本支持无／人工／AI 三种适配方式。人工绑定使用可选精度的静态对照图，通过官方面板通道显示，无需修改 Coo 的窗口转发规则。带滑杆的「模型设置」和「外观」均使用正式扩展面板；宿主自带的「配置」保留 schema 表单，页签采用宿主顺序。扩展安装不会修改 Coo 程序。生成预览图需要本机可用的 Chrome / Edge。

Coo 的「配置」保留完整配置总表，「模型设置」是同一份配置的个性化展示，并非另一套数据；「外观」只调整本扩展界面的配色、材质与光效。

人工和 AI 适配可循环播放识别到的原生 Idle 动作。未找到或未绑定的原生资源保留通用表现，动作词取决于实际导出的映射。HitAreas 原生点击反应和行走步态同步尚未支持。

## 安装与首次使用

在 Coo 的扩展页搜索或手动填写包名 `cortico-world-figure`，安装后重启，在扩展页确认状态为 `active`。从 **高级模式 → Live2D 模型一键安装** 打开面板。

使用准备好的本地安装目录时，在扩展页选择「本地目录」，选中含 `package.json` 的扩展文件夹。重启后可在 World 总览启用扩展。

也可以在实例实际使用的扩展目录中安装：

```powershell
corepack pnpm add cortico-world-figure
```

首次打包时，先确认形象包分发须知。打包 Live2D 模型还需确认 Core 和 SDK 许可。

1. 阅读形象包分发须知，点击「我已知晓，不再分发」。版本号始终位于面板右上角，仅底色由淡红变为淡绿；确认后主面板移除须知，普通升级不重复确认。
2. 阅读 Core / SDK 许可，点击「同意并获取」。扩展从 Live2D 官网下载 Core，从官方仓库获取固定版本的 Framework 源码。下载内容校验 SHA-256 后，在本机生成 Framework 和着色器并缓存。已同意许可的用户会自动复用或补齐缓存。

确认后的「须知」收在面板和设置底部的小入口，点击才展开；也可点击右上角版本号查看，普通升级不重复确认。

**扩展安装包不附带 Core、Framework 或着色器代码。生成的 Live2D 形象包会使用本机缓存中的运行组件，仅供本机使用。** 同样的提示会写进产物 `LICENSES.txt`。模型与第三方组件仍分别受各自许可约束。

## 日常流程

```text
拖入 / 粘贴 / 选择文件 → 一键安装 → 在 Coo 装扮页选择形象
```

模型目录应包含 `.model3.json` 及其引用的 `.moc3`、贴图等文件。把文件夹或 ZIP 拖入导入区；也可点击该区域后按 Ctrl+V 粘贴复制的文件、文件夹或完整路径。「选择文件夹」与「选择 ZIP」分别打开 Coo 窗口的系统目录、文件选择器；选中后自动识别模型和配套资源。

| 操作 | 实际行为 |
|---|---|
| 一键安装 | 在适配方式为「无」时，把识别到的模型打包并安装，或直接安装导入的现成形象包 |
| 一键打包 | 对已识别的模型生成形象包；按设置量取景、拍封面，完成后加入「已打包」 |
| 编辑 | 在弹窗中修改名称、简介、身体幅度和动作风格，直接保存到该份打包产物 |
| 安装 | 将选中的打包产物复制进 Coo 的 `figures/`；同名旧包先备份 |

导入时自动识别模型。可以点「一键安装」，也可以先用「一键打包」保留卡片，编辑后再安装。人工和 AI 适配仍需走各自的绑定或方案流程。已安装的副本可以从卡片再次安装，原模型目录移走后卡片也可继续使用。

「删除」只移除对应的打包产物，已安装形象不受影响。「清空旧打包」会保留最新一份，操作前再次确认。替换安装先复制新包，再交换目录，失败时保留或恢复原安装；备份默认保留最近两份。

## 导入文件夹或 zip

在导入区拖入、粘贴或选择文件，程序显示识别结果。同次导入包含多个模型时依次处理。安装失败或取消替换后可再次点击「一键安装」，沿用已打好的包并跳过已安装项。

| 导入内容 | 后续操作 |
|---|---|
| 原始 Live2D 模型，含 `.model3.json` | 一键打包并安装，或先保存卡片再编辑 |
| 现成形象包，含 `figure.json` | 一键安装，或先保留一份本机卡片副本 |

zip 单次最多 **32 MB**，解压后的内容也受 32 MB 限制；较大的原始模型可复制文件夹后粘贴导入。浏览器拖入文件夹时分批读取，总上限为 **512 MB**。导入会校验文件路径和包 ID，拒绝越界路径、无效名称及不在待装清单中的目录。导入、打包与自动删除均保留原始素材。

## BongoCat 模型

新版 BongoCat 模型文件夹和符合大小限制的 ZIP 可从同一入口一键安装。打包时保留原包的背景、封面和左右键位图，形象会跟随 Coo 的光标位置。带 Live2D 入口的旧 Mver 模型也可按普通模型导入。

全局键盘跟打留待宿主提供正式输入接口后接入。原生动作与装扮可通过人工绑定选择。

## 通用动作与表情适配

扩展沿用通用动作和表情配方，读取模型参数、匹配的 VTube Studio 配置及物理输入输出关系，自动寻找头部、身体、眼睛和嘴部的控制入口。标准映射保持原样；可明确判断的非标准入口自动修正，不要求为每个模型手写映射表。

参数含义、方向或物理关系不明确时，会跳过对应独立控制并说明限制；模型没有制作的动作和表情无法凭空补出。复杂模型按实际裁剪遮罩数量分配渲染缓冲，资源不足时自动尝试兼容模式并提示，避免脸部、嘴部等图层异常。

已有形象包包含打包时的运行代码。更新扩展后，需要重新打包、安装对应模型，才能应用新的参数识别与渲染修复。

## AI 自动适配

在「模型设置」中选择适配方式：无、人工或 AI；工作台顶部「设置」提供快捷弹窗。无使用通用配方；人工在导入后点击「预览并绑定」，通过左侧表情与动作、中间效果对照图、右侧原生资源完成绑定。表情显示默认/通用与所选效果两张图，动作显示三个带时间标记的取样帧；可切换组合与原生效果、重新取样、复位或恢复通用，未绑定项目继续使用通用配方。取样图不代表整段动作的流畅度，也可能漏掉短暂变化。「全部恢复通用」经确认清空当前草稿的绑定，保留原生资源，保存后生效。首次从原始模型保存会创建卡片；已有卡片的「动作」编辑更新原卡片，不增加卡片数量，未修改时不能重复保存。已安装副本仍需从卡片再次安装。旧包需重新导入后打包；原生资源库随新模型包保存，后续编辑不依赖原始目录。

保存期间锁定绑定编辑，提交失败保留草稿和原包；列表刷新或临时资源释放失败不撤销已保存的模型包。预览失败时暂停绑定与保存，可重试预览并保留当前草稿。编辑期间续期会话，关闭或切页后释放临时资源，过期会话自动回收。

切换装扮、部件、配饰或自定义选项时会自动测量可见底边。底边变化时保持模型原来的缩放比例并平移贴地，同时更新气泡和命中范围。切回默认会恢复原取景。已安装形象可从对应卡片重新安装，应用新版的自动贴地。

人工弹窗左侧可在「动作」与「装扮」间切换，两页共用对照区并一起保存。装扮保留「装扮」「部件」「配饰」三个内置组，可新增和删除自定义组。每组最多 16 个选项，组内单选，各组可同时生效。选项可绑定一个原生表情或动作末帧。共用参数的动作与装扮不能同时绑定。「恢复默认外观」只复位当前预览。

保存并重新安装后，这些分组出现在 Coo 自带的装扮页，由宿主保存当前选择。每个选项（含默认）按实际外观生成 128×128 缩略图；生成失败时保留原包和草稿，提示重试。预览中试穿不会修改已安装形象，也不会保存试穿状态。默认外观恢复模型与适配配置的初始值；动作仅提取末帧形成静态选项，不循环播放整段动画，不能为模型增加原本没有的服装或配色。

选择 AI 后，导入后 Coo 分析模型自带的 `.motion3.json` 和 `.exp3.json`，说明哪些资源对应通用动作或表情，再提交一份安装方案。也可直接告诉 Coo 模型完整路径，或在配置的模型搜索目录内按名字查找。遇到多个候选时先选择模型，不扫描整台电脑。

人工预览在独立临时副本中生成 PNG，经官方面板调用返回；设置窗口不加载模型脚本或额外端口页面。同一编辑弹窗复用后台浏览器与已加载模型，按实际就绪状态开始截图；切换资源只更新参数，切换精度才重建模型。预览支持 256／512／1024，默认 512，同时约束贴图、画布、遮罩及输出图片。可在「模型设置」保存默认值，也可在弹窗底部临时切换；保存与安装仍使用独立的正式画质。同一编辑会话内缓存已生成的图，快速切换只接收当前选择的结果，关闭后取消请求、退出后台浏览器并释放临时资源，不加入装扮库。

分析方式有自动、文本、文本＋图片。自动方式先看文件名、作者热键和参数曲线，必要时使用关键帧；文本方式不生成图片；文本＋图片在受限预算内生成关键帧。当前模型不接收图片或关键帧生成失败时，会说明原因并改用文本。单次分析最多附加六帧，不自动下载模型或其他运行环境。

「适配深度」仅在文本＋图片时启用，其他方式置灰并保留所选档位。快速使用基础取样；标准允许按资源、参数页和具体时刻补查；深入还要求对每项映射提供中性、通用表现、原生叠加及可用复位片段的静态对照。名称建议和 AI 自报置信度不能代替图片记录；深入档未取得对照、图片不可用或资源扫描不完整时，方案保留人工确认。静态对照供 AI 判断，不保证整段动作的语义和视觉表现一致。

默认每份方案确认一次：Coo 使用聊天气泡询问，也可以在面板中的方案条查看详情并确认。安装工具核对真实回答记录，不能通过模型自行填写一个“已确认”参数绕过。方案会绑定资源指纹，成品包同时校验所有文件；素材变化、方案过期或任务取消后须重新核对；成功方案重复调用只返回已有回执，不重复安装。

「自动安装」默认关闭。开启后，高置信度映射可以直接安装，不确定或涉及外观切换的映射保留通用表现。原生片段只影响其声明的参数，带状态的姿态需要复位片段；缺失、损坏或不明确的资源继续使用基础动作。

四个工具分别负责模型识别、动作识别、方案准备和安装。分析迟迟没有生成方案时，可在面板重新提交尚未完成的模型，无需再次导入。安装后返回形象 ID；需要穿上时由 Coo 使用宿主现有的 `pet_set`，并遵守桌宠的换装策略。本扩展不直接调用其他 World。为核对气泡确认，安装时只读取对应的 `desktop-pet` 提问和回答事件；面板同意后通过自己的安装完成事件交回 Coo 继续处理。

## 封面、取景与设置

「画质」提供流畅、标准、高清、原图四档，默认标准。前三档分别使用 1024、2048、4096 的贴图及渲染上限，贴图滑杆置灰并显示实际预设值；原图档开放贴图调节并恢复上次自定义值。原图不设软件画布上限，保留原始贴图；手动降低贴图精度时总档位显示自定义。画布随显示大小和屏幕像素比例调整，遮罩同步适配；设备尺寸或分配能力不足时明确显示实际限制，原图不会静默降低精度。已有形象包需要重新打包、安装后应用新运行时，修改设置不会直接重写旧包。

打包时默认使用系统已有的 Chrome / Edge 无头渲染，测量模型可见范围，生成 **512 × 512** 主封面和 **128 × 128** 选项小图。有取景结果时会写回 profile，再生成最终包。找不到浏览器、渲染失败或关闭封面时，会记录跳过原因，模型打包仍可完成。

设置可从面板顶部 **「设置」** 就地打开，也保留宿主配置页；面板底部显示实际安装目标。

独立的「外观」页提供「默认」与「自定义」方案。「默认」恢复改红色之前的完整样式：蓝色按钮、宿主底色、原有边角、紫色满档条与星点；保留自定义选择，切回后继续使用。自定义提供六种主题配色，以及星点、浮光、流星、爱心 ♥、气泡、光波六种粒子效果；另有哑光／磨砂玻璃／柔光／拉丝金属四种材质，可选择按钮纯色或渐变、跟随 Coo／浅色／深色，并调整边角与光晕。按钮、卡片、面板和弹窗一起换肤，布局和控件尺寸保持不变，仅影响本扩展。效果条与控件样本在滚动时悬浮于页面顶部，方便随时观察调整；修改后自动保存，保存失败可以重试。普通滑杆保持蓝色，系统启用减少动态效果时停止粒子动画。配置页与快捷设置集中于模型选项，外观设置独立保存。

| 设置 | 默认与作用 |
|---|---|
| 打包时拍封面 | 开启；关闭后同时跳过尺寸测量与封面渲染 |
| 贴图精度 | `original`，保留原精度；可选 4096 / 2048 / 1024 / 512 作为最长边上限 |
| 安装后删除打包产物 | 关闭；开启后安装成功会清掉对应卡片产物，只保留已安装副本 |
| 安装目录 | 留空时自动寻找 Coo 的 `figures/`，也可以指定目录 |

贴图降采样使用可选的 Python + Pillow；缺少它们时会记录提示。模型体积与实际显示效果取决于素材本身，不保证每个模型都能自动得到同样的取景和表情表现。

## 连续情绪与细微动作

生成的形象包集成 **SoulLink Emotion Engine `0.2.0-beta.1`**。它是本项目的表演组件：把 Coo 提供的情绪词转换成连续变化的表情和动作信号；模型读取、参数映射、打包和安装由本扩展负责。

### 从情绪词到模型参数

role 是表情和姿态的语义名称。

```text
Coo 的表情词 → SoulLink 的 VAD 情绪状态与 FACS 信号
             → 本扩展的语义 role → 模型实际的 Cubism 参数
```

`happy`、`sad`、`shy` 等词进入情绪预设，逐帧更新状态。本扩展将眉毛、嘴角、视线等信号翻译成 role，通过 `profile.roles` 对接实际参数，并平滑叠加通用表情配方。

| 表演内容 | 当前实现 |
|---|---|
| 表情过渡 | 连续更新情绪状态，让表情词之间的切换逐步发生 |
| 细微动作 | 输出头部、身体、视线、眨眼、呼吸与待机变化 |
| 模型适配 | 只处理模型已有的 role；缺少的通道跳过，不生成模型没有的能力 |

例如，收到 `happy` 时，表情预设会与眨眼、呼吸、待机微动共同作用，持续输出当前状态。缺少眉毛控制的模型仍使用可识别的嘴角、头部和身体通道，不会为了凑齐表情而写入服装、装饰等无关开关。更换模型仍沿用同一套通用流程；身体幅度和动作风格只是表演偏好，不承担逐模型修复映射的工作。

### 调整与分工

在卡片「编辑」里调整 **身体幅度（0.5×–3×）** 和 **动作风格（自然 / 活泼 / 安静 / 害羞）**。幅度影响身体微动强弱；风格影响手势、眨眼、呼吸和微动节奏。这些设置不控制走跑速度。保存直接更新打包产物，已安装的形象需要重新安装才能同步。

Coo Kit 负责行走、跑跳、坐下、拖拽和纯文字时的口型脉冲。Figure 朗读时按实际音频驱动开合，SoulLink 根据音量补充说话重音。表演引擎在本地计算。

「文字转语音」中的服务、音色和密钥留在扩展配置。Windows 可选择「跟气泡一起开始」，用首段播放回执对齐 Coo 原生气泡的起点，超时或语音失败时直接显示文字。已有形象从原卡重装后可读取同步口型。快速播报沿用按句提前合成。

默认转换沿用通用表演。AI 方案选中的 exp3 和 motion 会以数据形式写入独立的原生播放层，未映射的通道保留通用表现；不直接启用整套原生 pose3。表演效果依赖模型已有的参数，增加身体幅度不能补出缺失通道。

表演层初始化失败或运行异常时，会回退到通用离散表情配方，保留可用的基础表情和口型。扫描与卡片中的适配说明用于了解模型能力，受限通道会自动跳过，不要求用户逐个调整参数。

## 数据与包结构

默认数据位于扩展数据目录下的 `figure/`：`builds/` 保存打包产物，`sdk/` 缓存 Live2D 运行组件，`state.json` 保存卡片记录和须知确认。清理打包产物不会删除 Live2D 运行组件缓存。安装后的形象位于面板显示的 `figures/<id>/`，替换备份位于同级 `figure-backups/`。

`figure/automation.json` 保存适配方案及执行回执，旧记录会自动迁入，原文件保留。上传或 ZIP 解包的 AI 输入单独暂存，关闭面板不会使待确认方案丢失素材；过期输入会在后续启动或导入时清除，仍在有效方案中使用的素材会保留。原始本机模型目录始终只读。

形象包主要包含 `figure.json`、`figure.js`、`models/`、`backends/` 和 `sdk/`。包内保留 Live2D 后端与 SDK；公共 puppet 引擎由宿主通过 `opts.kit.createBody` 提供，工作台的 `body.js` / `rig.js` 预览副本不会进入产物。

## 常见情况

- **已安装但外观没有变化**：在 Coo 装扮页切换形象；如果编辑的是卡片产物，先重新安装。
- **有包但没有封面**：查看日志里的跳过原因，确认封面设置和系统浏览器。
- **模型很大，zip 导入失败**：改用文件夹导入，避免 zip 的 32 MB 限制。
- **提示运行组件缺失或校验失败**：在「须知」中重试获取 Live2D 运行组件。

## 开发与验证

源码以 TypeScript / ESM 编写，要求 Node.js 22 或更新版本。当前完整流程在 Windows 验证；其他系统的封面功能取决于是否能找到并启动相应浏览器。

```powershell
npm ci
npm test
npm run check
npm run build:ui
```

无模型时执行独立回归；真实模型集成测试还需指定自己的模型，以及已同意许可并校验过的 Live2D 运行组件缓存：

```powershell
$env:L2D_MODEL = 'D:\models\your_model'
$env:L2D_CORE = 'D:\Coo-data\figure\sdk\live2dcubismcore.min.js'
npm test
```

`L2D_CORE` 指向缓存目录中的 Core，旁边需有 `framework.js` 和 `shaders.js`。测试复用整套缓存，不自动下载；构建、安装均写入临时目录。`src/` 为 World、自动化、导入与流水线，`src/webui/` 是面板源码，`dist/` 是生成的浏览器产物；`workbench/` 提供模型转换和运行时；`test/` 包含回归用例。`build:ui` 为界面生成内容摘要文件名，避免同一开发版本使用旧缓存；打包前自动执行。

发布前重新阅读 Pal-AI-Lab 官方扩展要求，从 Cortico 检出目录执行 `pnpm describe:extension <本包目录>` 和 `pnpm check:extension <本包目录>`，核对契约、自描述、标签与安装包。已有更新日志只记录主要功能及适配变化，界面微调不单独写版本记录；没有日志的项目不另建。
