# Live2D 模型一键安装

把本地 Live2D 模型转换成 Coo / Coopanion 可用的形象包，自动识别通用动作与表情参数，生成封面并安装。每份产物保留为卡片，可以修改名称、简介和表演风格，再安装到桌宠中。

这是运行在 Coo 内的 World 扩展。模型处理在本机完成，不经过对话；使用扩展无需另装 Node.js，也无需手动启动浏览器。操作由面板触发，不向模型声明工具、事件或环境提示词。本项目不附带模型素材。

## 安装与首次使用

在 Coo 的扩展页搜索或手动填写包名 `cortico-world-figure`，安装后重启，在扩展页确认状态为 `active`。从 **高级模式 → Live2D 模型一键安装** 打开面板。

也可以在实例实际使用的扩展目录中安装：

```powershell
corepack pnpm add cortico-world-figure
```

首次使用先完成两项准备：

1. 阅读形象包分发须知，点击「我已知晓，不再分发」。版本号始终位于面板右上角，仅底色由淡红变为淡绿；确认后主面板移除须知，普通升级不重复确认。
2. 阅读 Core / SDK 许可，点击「同意并获取」。扩展从 Live2D Inc. 官方服务器下载 Cubism Core，校验长度和 SHA-256 后缓存到本地，后续复用已获取的文件。

确认后的「须知」入口默认折叠。提供配置页脚支持的宿主会将其放在本扩展「配置」页左下角；没有该支持的官方宿主保留独立「须知」页签，扩展安装无需修改宿主。

**扩展本身不附带 Core，但生成的形象包包含 Live2D Cubism Core。请仅在本机使用，不要上传、分享或再次分发这些形象包。** 同样的提示会写进产物 `LICENSES.txt`。模型与第三方组件仍分别受各自许可约束。

## 日常流程

```text
填写模型目录 → 扫描 → 打包 → 编辑卡片信息 → 安装
```

模型目录应包含 `.model3.json` 及其引用的 `.moc3`、贴图等文件。可以直接填写绝对路径，也可以从「导入」选择文件夹。

| 操作 | 实际行为 |
|---|---|
| 扫描 | 显示参数、语义 role 数，以及自动修正和受限通道；不生成形象包 |
| 打包 | 生成形象包；按设置量取景、拍封面，完成后加入「已打包」 |
| 编辑 | 修改名称、简介、身体幅度和动作风格，直接保存到该份打包产物 |
| 安装 | 将选中的打包产物复制进 Coo 的 `figures/`；同名旧包先备份 |

扫描、打包和安装各自触发，不会自动连跑；扫描也不是打包的硬性前置步骤。编辑完成后，已安装的副本需要再点一次「安装」才会更新。安装现有卡片不要求原模型目录仍然存在。

「删除」只移除对应的打包产物，已安装形象不受影响。「清空旧打包」会保留最新一份，操作前再次确认。替换安装先复制新包，再交换目录，失败时保留或恢复原安装；备份默认保留最近两份。

## 导入文件夹或 zip

点击「导入」后选择文件，也可以把 zip 或模型文件夹拖进弹层。程序会列出识别到的内容，由你决定下一步。

| 导入内容 | 后续操作 |
|---|---|
| 原始 Live2D 模型，含 `.model3.json` | 点「打包」，产物加入卡片列表；可以先编辑再安装 |
| 现成形象包，含 `figure.json` | 点「安装」；若同名已存在，确认后备份替换 |

zip 单次最多 **32 MB**，解压后的内容也受 32 MB 限制；较大的原始模型请选文件夹，分批上传的总上限为 **512 MB**。导入会校验文件路径和包 ID，拒绝越界路径、无效名称及不在待装清单中的目录。

## 通用动作与表情适配

扩展沿用通用动作和表情配方，读取模型参数、匹配的 VTube Studio 配置及物理输入输出关系，自动寻找头部、身体、眼睛和嘴部的控制入口。标准映射保持原样；可明确判断的非标准入口自动修正，不要求为每个模型手写映射表。

参数含义、方向或物理关系不明确时，会跳过对应独立控制并说明限制；模型没有制作的动作和表情无法凭空补出。复杂模型按实际裁剪遮罩数量分配渲染缓冲，资源不足时自动尝试兼容模式并提示，避免脸部、嘴部等图层异常。

已有形象包包含打包时的运行代码。更新扩展后，需要重新打包、安装对应模型，才能应用新的参数识别与渲染修复。

## 封面、取景与设置

打包时默认使用系统已有的 Chrome / Edge 无头渲染，测量模型可见范围，生成 **512 × 512** 主封面和 **128 × 128** 选项小图。有取景结果时会写回 profile，再生成最终包。找不到浏览器、渲染失败或关闭封面时，会记录跳过原因，模型打包仍可完成。

高级设置位于本扩展的 **「配置」页签**；面板底部显示实际安装目标。

| 设置 | 默认与作用 |
|---|---|
| 打包时拍封面 | 开启；关闭后同时跳过尺寸测量与封面渲染 |
| 贴图精度 | `original`，保留原精度；可选 4096 / 2048 / 1024 / 512 作为最长边上限 |
| 清理 | 关闭；开启后隐藏识别到的水印 / 文字部件，按作者提供的状态固定相关参数 |
| 安装后删除打包产物 | 关闭；开启后安装成功会清掉对应卡片产物，只保留已安装副本 |
| 安装目录 | 留空时自动寻找 Coo 的 `figures/`，也可以指定目录 |

贴图降采样使用可选的 Python + Pillow；缺少它们时会记录提示。模型体积与实际显示效果取决于素材本身，不保证每个模型都能自动得到同样的取景和表情表现。

## 连续情绪与细微动作

生成的形象包集成 **SoulLink Emotion Engine `0.2.0-beta.1`**。它是本项目的表演组件：把 Coo 提供的情绪词转换成连续变化的表情和动作信号；模型读取、参数映射、打包和安装由本扩展负责。

### 从情绪词到模型参数

role 是表情和姿态的语义名称。

```text
Coo 的表情词 → SoulLink 的 VAD 情绪状态与 FACS 信号
             → 本扩展的语义 role → 模型实际的 Cubism 参数
```

`happy`、`sad`、`shy` 等词进入情绪预设，逐帧更新状态。本扩展将眉毛、嘴角、视线等信号翻译成 role，通过 `profile.roles` 对接实际参数，并平滑叠加通用表情配方。

| 表演内容 | 当前实现 |
|---|---|
| 表情过渡 | 连续更新情绪状态，让表情词之间的切换逐步发生 |
| 细微动作 | 输出头部、身体、视线、眨眼、呼吸与待机变化 |
| 模型适配 | 只处理模型已有的 role；缺少的通道跳过，不生成模型没有的能力 |

例如，收到 `happy` 时，表情预设会与眨眼、呼吸、待机微动共同作用，持续输出当前状态。缺少眉毛控制的模型仍使用可识别的嘴角、头部和身体通道，不会为了凑齐表情而写入服装、装饰等无关开关。更换模型仍沿用同一套通用流程；身体幅度和动作风格只是表演偏好，不承担逐模型修复映射的工作。

### 调整与分工

在卡片「编辑」里调整 **身体幅度（0.5×–3×）** 和 **动作风格（自然 / 活泼 / 安静 / 害羞）**。幅度影响身体微动强弱；风格影响手势、眨眼、呼吸和微动节奏。这些设置不控制走跑速度。保存直接更新打包产物，已安装的形象需要重新安装才能同步。

Coo Kit 负责行走、跑跳、坐下、拖拽与说话口型。本集成关闭 SoulLink 的独立口型，避免重复驱动；没有接入其独立 LLM 情绪识别、TTS 或语音规划服务。表演引擎在本地计算，无需额外联网。

当前转换器采用简易模式，不绑定模型原生 exp3、不播放原生 motion、不加载 pose3；motion 仅用于提取部分部件透明度基线。表演效果依赖模型已经制作的参数；通用适配会自动识别可确认的控制入口，增加身体幅度不能补出缺失通道。

表演层初始化失败或运行异常时，会回退到通用离散表情配方，保留可用的基础表情和口型。扫描与卡片中的适配说明用于了解模型能力，受限通道会自动跳过，不要求用户逐个调整参数。

## 数据与包结构

默认数据位于扩展数据目录下的 `figure/`：`builds/` 保存打包产物，`sdk/` 缓存 Core，`state.json` 保存卡片记录和须知确认。清理打包产物不会删除 Core 缓存。安装后的形象位于面板显示的 `figures/<id>/`，替换备份位于同级 `figure-backups/`。

形象包主要包含 `figure.json`、`figure.js`、`models/`、`backends/` 和 `sdk/`。包内保留 Live2D 后端与 SDK；公共 puppet 引擎由宿主通过 `opts.kit.createBody` 提供，工作台的 `body.js` / `rig.js` 预览副本不会进入产物。

## 常见情况

- **已安装但外观没有变化**：在 Coo 装扮页切换形象；如果编辑的是卡片产物，先重新安装。
- **有包但没有封面**：查看日志里的跳过原因，确认封面设置和系统浏览器。
- **模型很大，zip 导入失败**：改用文件夹导入，避免 zip 的 32 MB 限制。
- **提示缺少核心或校验失败**：在面板获取 Core；校验不通过时不会打包。

## 开发与验证

源码以 TypeScript / ESM 编写，要求 Node.js 22 或更新版本。当前完整流程在 Windows 验证；其他系统的封面功能取决于是否能找到并启动相应浏览器。

```powershell
npm ci
npm test
npm run check
npm run build:ui
```

无模型时执行独立回归；真实模型集成测试还需指定自己的模型，以及已同意许可、校验过的 Core：

```powershell
$env:L2D_MODEL = 'D:\models\your_model'
$env:L2D_CORE = 'D:\Coo-data\figure\sdk\live2dcubismcore.min.js'
npm test
```

测试复用 Core，不自动下载；构建、安装均写入临时目录。`src/` 为 World、导入与流水线；`dist/` 为手写面板；`workbench/` 提供模型转换和运行时；`test/` 包含回归用例。`build:ui` 为界面生成内容摘要文件名，避免同一开发版本使用旧缓存；打包前自动执行。

发布前重新阅读 Pal-AI-Lab 官方扩展要求，从 Cortico 检出目录执行 `pnpm describe:extension <本包目录>` 和 `pnpm check:extension <本包目录>`，核对契约、自描述、标签与安装包。已有更新日志只记录主要功能及适配变化，界面微调不单独写版本记录；没有日志的项目不另建。
